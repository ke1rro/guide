# Contributing

Цей репозиторій містить гайди, налаштування та додаткові матеріали для курсів ПОК/АКС.

Якщо ви знайшли помилку, застарілу інструкцію або хочете додати корисний матеріал — pull request-и вітаються.

## Що можна додавати

Вітаються:

- виправлення помилок та неточностей;
- оновлення застарілих інструкцій;
- додаткові пояснення до існуючих гайдів;
- альтернативні способи налаштування середовища;
- корисні інструменти та посилання для ПОК/АКС;
- скріншоти, якщо вони допомагають зрозуміти конкретний крок;
- покращення структури або читабельності документації.

Не варто додавати матеріали, які не повʼязані з курсами або просто дублюють вже наявну інформацію.

## Стиль тексту

Пишіть українською мовою, просто і по суті.

Це практичний гайд, тому краще написати:

> Встановіть `clang-format` через Homebrew:

ніж додавати довгий вступ про те, що таке форматування коду.

Назви команд, файлів, програм та опцій оформлюйте через backticks:

`clang-format`, `.clang-tidy`, `Virtualize`, `arm64`.

Команди оформлюйте окремими блоками:

```bash
clang-format -i main.cpp
```

Для додаткової інформації можна використовувати GitHub alerts:

```md
> [!NOTE]
> Коротка додаткова інформація.
```

Для важливих застережень:

```md
> [!WARNING]
> Інформація, яку варто прочитати перед виконанням наступного кроку.
```

Не додавайте зайвих `NOTE`/`WARNING`, якщо інформацію можна нормально написати звичайним текстом.

## Скріншоти

Скріншоти зберігаються у:

```text
.github/imgs/
```

Для великих гайдів використовуйте окремі директорії, наприклад:

```text
.github/imgs/ubuntu/
.github/imgs/utm/
```

Назви файлів мають бути короткими та зрозумілими:

```text
utm-arm64-01.png
utm-arm64-02.png
ubuntu-server-ssh.png
```

Скріншот має допомагати пройти конкретний крок, а не просто дублювати текст.

Перед додаванням перевірте, що на зображенні немає:

- паролів;
- токенів;
- приватних ключів;
- серійних номерів;
- особистих даних;
- іншої інформації, яку не варто публікувати.

## Посилання

За можливості використовуйте офіційну документацію та першоджерела.

Наприклад:

- документацію Apple;
- документацію Ubuntu;
- документацію UTM;
- документацію LLVM/GCC;
- матеріали курсів на `learn.ucu.edu.ua`.

Не додавайте tracking-параметри до URL, якщо вони не потрібні:

```text
?utm_source=...
?ref=...
```

Перед створенням PR перевірте, що всі нові посилання відкриваються.

## Перевірка інструкцій

Якщо ви додаєте або суттєво змінюєте інструкцію, бажано пройти її самостійно на реальному середовищі.

Особливо це стосується:

- встановлення операційних систем;
- UTM / Parallels / Docker;
- налаштування toolchain;
- роботи з USB-пристроями;
- команд, які змінюють систему або конфігурацію.

Якщо певний крок ви не перевіряли самостійно, зазначте це в описі PR.

Не варто подавати припущення як гарантовано робоче рішення.

## Markdown та pre-commit

У репозиторії використовується `pre-commit`.

Перед створенням PR бажано запустити:

```bash
pre-commit run --all-files
```

Якщо `pre-commit` ще не встановлений:

```bash
brew install pre-commit
pre-commit install
```

Після автоматичного форматування перегляньте зміни:

```bash
git diff
```

Не додавайте до репозиторію тимчасові файли, build artifacts, `.DS_Store`, IDE cache та інші локальні файли.

## Pull Request

Перед створенням PR:

1. Перевірте, що Markdown нормально відображається на GitHub.
1. Перевірте нові команди та посилання.
1. Переконайтесь, що скріншоти знаходяться у правильній директорії.
1. Запустіть `pre-commit`.
1. Перегляньте `git diff`.
1. Коротко опишіть, що саме ви змінили і навіщо.

Для невеликих виправлень достатньо одного commit.

Для більших змін бажано не змішувати в одному PR декілька неповʼязаних тем.

## Issues

Якщо ви знайшли проблему, але не хочете або не можете зробити PR, створіть Issue.

Бажано вказати:

- де саме знаходиться проблема;
- що зараз написано або відбувається;
- що очікувалось;
- версію macOS / Ubuntu / інструмента, якщо це має значення;
- скріншот або лог, якщо вони допомагають відтворити проблему.

Для помилки в конкретній інструкції додайте посилання на відповідний файл або секцію.
